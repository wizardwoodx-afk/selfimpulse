# Audit response — 2026-09-30 (external review, "DO NOT SHIP")

An external review of this tree reported four critical exploits and eight high
findings against the shipped guarantees. Every claim below was re-executed
against this commit before anything was changed, using
[`probe/proofLayerIntegrity.test.ts`](../../probe/proofLayerIntegrity.test.ts) —
a probe written as the reproduction, so the fixes are pinned and the failures
cannot come back silently.

Verdict on the report: **the four criticals were real and reproduced.** Two of
its other claims did not match this revision and are corrected below rather than
quietly dropped.

## Verified as reported — and the ones that were not

Corrections, with the evidence:

- **C4 is latent, not live.** `verifyLicenseKey` and `rememberLicense` have **no
  call sites** in `src/`: nothing verifies a key and nothing stores one, so a
  forged pro key cannot currently unlock anything (`currentEdition()` resolves
  from stored state). The forgeable verifier was real; the exploit path was not.
  The probe asserts the absence of callers, so wiring it up later forces the
  question of which assurance is required.
- **The palette-drift diagnosis does not match this revision.** The report says
  `graph3d.test.ts:88` asserts `#0D1010`. In this tree it asserts
  `/--bg:\s*#000000/i.test(css) && !/#0D1010/i.test(css)` — the exact opposite —
  and no suites failed except the two that needed `pytest`/`cargo`, which are
  absent in a bare container. With `pytest` installed the gate is green on the
  pre-change tree.
- **`wiring.test.ts` does assert.** The report says it computes `dropped[]` and
  only prints it. It carries three assertions and an explicit "audit H5: this
  suite used to only PRINT" note; it exits non-zero on failure.
- **`release.yml` does publish.** The report says it never builds a release.
  It carries a `publish` job (source archive + SHA256SUMS + GitHub release) and
  a comment recording that stopping-after-verification was the old bug.
- **`controlPlane.test.ts:8` does not claim `cargo test` runs here.** It says the
  opposite — that the environment has no cargo, so it pins source-level
  invariants. The substantive point stands and is listed below.

## Still open (not fixed here, deliberately)

These are real and were **not** silently dropped:

1. **`git_*` bypasses workspace containment** (`src-tauri/src/git.rs`) — six
   commands take a WebView-supplied `cwd` and never call `ensure_allowed`. The
   other fs paths do. Fixing it means threading `AppState` into those commands,
   and **this environment has no Rust toolchain**, so the change could not be
   compiled or tested. It should not be made blind.
2. **`hermes.rs` spawns Python with an inherited environment** (no `env_clear`,
   blocking `wait` with no timeout).
3. **`policyGateway` is default-allow** over a three-name risky set
   (`workspace_write`, `dispatch_mission`, `shell_exec`): a differently-named
   destructive tool is allowed. It is wired into the real dispatch throat, so
   changing the default is a behavioural change that deserves its own review.
4. **`expression.ts` compiles with `new Function`, and the desktop CSP
   (`script-src 'self'`) forbids `unsafe-eval`** — so in the desktop build the
   sandbox cannot run and `controlRuntime` silently degrades a condition to
   `Boolean(first)`. It works in the dev web build, which is why this is easy to
   miss. The fix is to fail closed (refuse the node) rather than fall back to
   truthiness.
5. **`cargo test` runs in no gate.** The Rust unit tests ship in the tree and are
   never executed by CI.
6. **CI hygiene** — actions pinned to mutable `@v4` tags, no `timeout-minutes`,
   no top-level `permissions:` on `gate.yml`.
7. **The proof is only as strong as the signer's key store** — in the browser
   host path the Ed25519 private key is mirrored into `localStorage`
   (`src/mission/signing.ts`). Stated in the code as a trade-off; unchanged here.

## What this does to the wire format

`si-proof-receipt/2` receipts minted **before** this change are refused by name
("carries no `si-seal/2` header binding") rather than accepted on trust: their
header genuinely cannot be shown unaltered. The frozen legacy wire
(`mj-proof-receipt/1|2`) keeps its historical semantics byte for byte, so
receipts already issued under those formats verify exactly as before. The
product is unreleased 1.0.0 and no receipt has been issued to a customer.
