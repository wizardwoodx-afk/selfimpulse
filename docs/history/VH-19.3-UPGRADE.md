# Vouch Harbor 19.3.0 "Vanguard" — upgrade notes

Base: 19.2.0 "Armada". 19.3.0 is the **fleet-becomes-real release**,
answering the three capability gaps the 19.2.0 review named: the Captain
now **reasons** over its members' outputs instead of merely reporting them,
the live-data GuardRail now performs **actual source retrieval** when an
evidence fetch is wired, and the 460 specialists stop being prompt personas —
they now **execute real tool calls**, every one of them gated and
receipted. Protocol unchanged at v0.10.7.

Vanguard (n.): the ship that leads the fleet. 19.2.0 made the fleet
honest; 19.3.0 makes it work.

## 1 · The specialists are executors now — a real act/observe loop

The review was right: 460 specialists producing "specialized reasoning"
is prompt engineering at scale, not an agentic system. 19.3.0 adds the
execution substrate, built the VH way — **verifiable execution**, the
exact opposite of a black-box cloud agent:

```
specialist carries a toolset (category-bound, ≤ 3 tools, never by name)
  ↓
member run = a loop: provider call → tool blocks? → validate → gate →
             execute → receipt → feed the REAL result back → repeat
  ↓
stops clean when the model answers, or at MAX_AGENT_STEPS (3), labelled
```

- `src/vh19/tools.ts` — five tools a reviewer can read in one sitting:
  `fs.list`, `fs.read` (safe), `fs.write`, `net.fetch` (risky — human gate,
  always), `wiki.search` (safe, pinned to the public Wikipedia endpoint —
  arbitrary egress stays gated). Filesystem tools are workspace-rooted;
  traversal and absolute paths are refused before anything touches disk;
  network egress reuses the product's SSRF guard even THROUGH an approved
  gate.
- `src/vh19/agentLoop.ts` — the loop itself. Every attempted call lands a
  receipt (`vh19-tool/1` digest): executed, failed, gated-out or refused —
  nothing silent. A gate denial travels back to the model VERBATIM; the
  model never sees a fabricated tool result. A truncated loop is labelled,
  never dressed as done. Toolless members keep the exact 19.2.0
  single-call path.
- Member receipts (`vh19-member/1`) now commit to the member's tool
  receipts — the evidence chain covers EFFECTS, not just text.
- Wired via `deps.workspaceRoot`: no workspace ⇒ no tools ⇒ 19.2.0
  semantics, bit for bit. Probe-pinned: `probe/agentTools`, 47 checks.

## 2 · Captain synthesis — reasoned collaboration, not a report

The review's capability gap: 19.2.0 executed N members, then the Captain
reported N sections. 19.3.0 closes it in `src/vh19/synthesis.ts`:

```
executed member answers
  ↓
deterministic divergence pass — claim atoms (percentages, dates, money,
versions, URLs): corroborated vs single-sourced, computed not asserted
  ↓
the Captain's OWN provider call under its OWN prompt — compare, reconcile,
name which member supports what; never invent facts none produced
  ↓
one coherent domain result, member sections kept below as evidence
```

Honesty edges, probe-pinned (`probe/synthesis`, 29 checks): synthesis is
its OWN call with its OWN token-ledger entry and its OWN receipt digest —
never a relabel; it runs only over EXECUTED answers and only with ≥ 2 of
them; a failed synthesis call keeps every member answer and says synthesis
was attempted and failed; stray tool fences are stripped from the
synthesis text before user or digest. The response digest now commits to
the synthesis record.

## 3 · The GuardRail retrieves — "verified" means fetched

The review's strongest point: a model could satisfy 19.2.0's evidence test
with a fabricated citation. `verifyLiveEvidence()` in
`src/vh19/liveData.ts` is the fix, wired via `deps.evidenceFetch`:

```
time-sensitive claims detected
  ↓
fetch each cited URL (≤ 3, 8s timeout, injected fetch)
  ↓
claim markers found INSIDE the fetched source?
  ↓
supported ⇒ verified, verifiedBy: "retrieval" (receipted: url, HTTP
status, claim hits, fetchedAt timestamp, bytes)
unsupported/unfetchable ⇒ the flag stands, receipted as failed
no evidenceFetch wired ⇒ disclosure-only, verifiedBy: "disclosure"
```

The earning mechanism rides in the canonical — a disclosure stamp can
never pose as a retrieval stamp (`probe/liveData`, 27 checks). Honest
boundary, restated: VH still ships no web-search provider by default;
verification is a wired capability, and its absence is labelled, never
papered over.

## 4 · Unchanged, still true

19.2.0's multi-member execution (now with member agent loops inside it),
the Shipyard, the Captain hierarchy, the failure taxonomy, the 460-bench,
the legacy-compat registry, the prompt-budget optimizer (estimates still
labelled estimates). Every 19.2.0 honesty rule remains pinned.

## 5 · What we did NOT do, honestly

- No computer-use/browser automation and no app connectors — VH stays a
  local-first governance+execution layer; cloud-desktop agent play is a
  different product, and we are not pretending otherwise.
- No routines/scheduler yet — scheduled missions are the next candidate.
- Tool count stays at five on purpose. More tools ship only with their own
  gates, receipts and probes.
