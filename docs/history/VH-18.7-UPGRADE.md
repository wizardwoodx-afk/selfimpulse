# Vouch Harbor 18.7.0 "Keystone" — upgrade notes

Base: 18.6.0 "Polaris". 18.7.0 answers the 18.6.0 review point for point:
the two release-contract bugs are fixed, goal reporting tells the truth, the
offline verifier runs ~2× faster so a reviewer's execution window can finish
it, and the A2A base gains the thing it was missing — an accountable handoff
ledger. No new architectural layer; the spine is unchanged. Protocol v0.10.7.

## 1 · Goal truthfulness (the review's DONE/PARTIAL/PLANNED/BLOCKED ask)

A goal of five planned steps no longer reads "done". `state: "done"` now
requires every step EXECUTED; a terminal goal with unexecuted steps settles
as `"settled"`, and a new honest verdict — `goalStatus()` — reports:

```text
DONE         every step actually executed
PARTIAL      some executed, rest planned/refused
PLANNED      everything planned, nothing ran
BLOCKED      nothing executed; a refusal stopped it
IN-PROGRESS  steps still open or gated
```

The Assignments panel shows the verdict as a stamp plus two numbers that no
longer lie: `executed %` (what ran) and `settled %` (what was decided).
`probe/goals` pins the taxonomy (26 checks, +7).

## 2 · The A2A handoff ledger

Every delegation attempt through the peer seam now gets a receipt —
**including the refusals**. `src/vh19/handoffs.ts` records peer, task
digest, outcome, reason-in-words, the peer's receipt digest when a bridge
executed, and a timestamp. The door shows it in the collaboration panel:
a handoff that never ran is stamped `REFUSED — no bridge wired, nothing
sent`; a handoff that ran carries `peer-receipt <digest>…`. The
peerDelegate contract grew an optional `receiptDigest` so a real bridge's
receipt travels end-to-end into the log. Nothing is recorded that did not
happen; nothing that happened goes unrecorded. (`probe/vh19` +2 = 81.)

Why a ledger instead of a network transport: a browser-to-peer wire would be
a new architectural layer with a new trust surface. The ledger is the part
that was actually missing — collaboration you can AUDIT — and it sits on the
existing bridge seam, ready for any transport the host wires later.

## 3 · Release-contract fixes (the review's concrete findings)

  • **VERIFY.sh no longer hardcodes a version or a suite count** — the 18.4.0
    "111 suites" header that outlived two releases is gone; the header now
    derives the count from `verify/suites/` itself and prints BUILD-INFO's
    identity line. Stale-by-construction is now impossible.
  • **The offline verifier is ~2× faster** — independent suites run in a
    bounded pool (≤6, cpu-capped) with per-suite attribution preserved:
    output is buffered and printed in deterministic sort order. The 18.6.0
    reviewer's environment timed out mid-pack; the same tree now finishes
    with margin. SKIP-needs-node_modules honesty semantics unchanged —
    skipped suites are still counted separately, never as passes.
