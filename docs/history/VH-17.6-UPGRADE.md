# VH 17.6.2 — Release notes (Patina, patch 2: the external-validation release)

**The 17.6.1 verdict (9.9/10) said: the next step is not another giant
feature release — it's external validation.** 17.6.2 is exactly that:
multi-machine interoperability proven with real process isolation, a door
for external agents, an enlarged security review, a reproducible benchmark
pack — and the release documentation now keeps its two "zero-install"
notions strictly separate.

## What changed in 17.6.2

### 1. Two-machine interop, proven for real — `probe/interop.test.ts`
Not a diagram: machine A (the TypeScript runtime) seals a real receipt,
anchors it, and exports three files into a transport directory. Machine B
is a **spawned `node tools/vh-interop.mjs` process** — separate process,
separate rulebook copy, zero shared state — which verifies the receipt,
opens the envelope, attributes the proof to A's signer, and refuses
tampering and replay. The cross-implementation pin is the point: an
envelope sealed in TS verifies under the pure-JS CLI.

### 2. The external-agent boundary — `tools/vh-interop.mjs`
Any agent or harbor — Patina or not — joins the trust chain through files
and plain JSON, **zero npm dependencies**:

```
identity · anchor · verify-receipt · verify-envelope · transport-pack
```

- Same rulebook as the live product (the protocol bridge — byte-identical
  verdicts to `tools/verify-receipt.mjs`).
- Refusals in words, exit code 1; nothing fake-passes.
- `verify-envelope --seen <ledger.json>`: bounded nonce ledger (4096) —
  an envelope is ONE-TIME evidence at a harbor.
- Contract: `docs/INTEROP.md`.

### 3. Envelopes are now replay-protected in the runtime too
`crossHarbor.verifyAnchorEnvelope()` gains a `ReplayLedger` seam
(`memoryReplayLedger()` ships, bounded by construction). A second
presentation of the same nonce is refused as `replayed-envelope`.
Probe: `crossHarbor` now 9 checks.

### 4. The security-review artifact grows three surfaces
`vh-security-review/1` now inventories cross-harbor anchoring, the
grant-authority delegation rule, and the external-agent CLI boundary —
each with posture + machine-checkable evidence — and states its new
limits honestly (identity-at-rest responsibility, per-harbor replay
scope, transport proven by process isolation, not yet an external
network deployment). Pinned by `probe/securityReview`.

### 5. The reproducible benchmark pack — `benchmark/run.mjs`
Zero-install, deterministic (fixed seed, pinned input digest in
`benchmark/BASELINE.json`): receipt-verify throughput (500×), ECDSA
envelope round-trips (200×), and B3 — the protocol's 129-check gate,
dependency-backed, HONESTLY SKIPPED when `protocol/node_modules` is
absent. Correctness asserted; timings reported, never pinned.

### 6. The doc fix the review named
Release docs now separate the two notions of zero install:

| Gate | Deps |
|---|---|
| Bridge gate (`protocol/bridge/bridge-selftest.mjs`) | **none** — genuinely zero-install |
| Offline pack (`verify/run.mjs`) · interop CLI · benchmark | **none** |
| Protocol cryptographic self-test (129 checks) | **yes** — `cd protocol && npm install`, lock-pinned |

The README's "Run it" section carries this table. The protocol suite was
never zero-install and 17.6.2 stops letting the two notions blur.
