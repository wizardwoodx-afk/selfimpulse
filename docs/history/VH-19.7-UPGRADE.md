## What this release is

19.7.0 "Recall" is the memory-and-mastery release. Four movements, each
probe-pinned, each honest by construction:

1. **The console grew a craft layer** — and the preview bug that kept
   embedded frames on the splash forever is fixed at the root.
2. **Every conversation becomes a graph you can re-enter** — the user-facing
   star: chat history as keyword nodes, co-occurrence edges, dated sessions,
   and rehydration that is always MARKED, never a silent injection.
3. **The token optimizer became a pipeline** — every provider call in the
   product now rides normalize → dedup → cache-alignment → budget, with the
   per-run delta rendered on the reply itself.
4. **The fleet grew up** — the MCP market (add ANY server), an A2A replay
   guard, and a member loop that auto-repairs transient failures without
   pausing a human.

Codename lineage: Seal → Patina → Warrant → Reach → **Federation** → **Recall**.

## 1. The console, v2 (the preview fix included)

### The preview bug, named and closed

A sandboxed preview iframe runs the app under an OPAQUE origin
(`origin: null`). Vite's dev middleware answered such origins with a 403
(CORS), so **no module ever loaded** and the frame sat on the static splash
forever — observed, reproduced headlessly, and fixed:

- `vite.config.ts` gained the `vh-preview-cors` plugin: permissive CORS on
  every response, preflights answered, vite's own CORS gate disabled
  (`server.cors: false`). Dev-server only; the production build is
  same-origin and does not need it.
- `src/main.tsx` no longer injects the strict browser CSP inside a sandboxed
  frame — under a null origin `'self'` matches nothing, so the policy would
  blacklist the very scripts booting the app. Detection cannot lie: an
  opaque frame cannot reach `window.top`'s document (throws), while any
  top-level page and the Tauri webview can. The relaxed context is stated
  in the console, not hidden.
- The boot splash's light `<html>` canvas is retired two frames after
  React mounts, so the dark console no longer leaks a light page behind it.

Verified headlessly with the exact sandbox attribute
(`sandbox="allow-scripts"`, origin `null`): the app mounts (`html.nx`),
boots with **zero page errors**, and the chat works end to end.

## 2. The memory graph — conversations as re-enterable graphs

`src/vh19/memoryGraph.ts` · `probe/memoryGraph` 26 checks.

The idea, implemented literally: **each chat becomes a graph of its
keywords.** Nodes are keywords (weight = sessions seen in), edges are
co-occurrence within a session, and each session carries its dated,
capped transcript, its keyword list and a content digest.

- **Deterministic extraction** (`extractKeywords`): tokenize → drop
  stopwords/numbers → score by frequency × length with a proper-noun
  bonus → stable sort. Same text in, same graph out — pinned.
- **Recall in the user's own words**: "what happened with the Zephyr
  migration?" matches session keywords AND message text; "on 12 september…"
  parses a date window (`parseDateWindow`: relative days/weeks/months,
  yesterday/today, ISO, "12 march 2026"); a date miss demotes hard; an
  unrelated query honestly returns `[]`.
- **Rehydration is marked**: `rehydrate()` emits a preamble — title, dates,
  keywords, the most recent turns trimmed — that rides the user's message
  INSIDE explicit `── rehydrated context ──` markers with an end line. No
  member or captain can mistake it for live memory; the console also shows
  a `↻ rehydrated "…"` chip on the message that carried it.
- **Idempotent upsert**: a growing chat re-ingests the same session id;
  weights and edge counts count it once. Local-first storage with a
  module-memory mirror for storage-less runtimes; the Memory Graphs plane
  renders the graph as SVG (nodes sized by weight, edges by strength) and
  lists sessions with Continue / forget.

## 3. The token pipeline — every call, measured

`src/vh19/tokenOptim.ts` (pipeline) · `src/vh19/providers.ts` (the choke
point) · `probe/tokenPipeline` 20 checks.

The 19.1.0 budget-fitter grew into a four-stage pipeline through which
**every provider call in the product now passes** (`complete()` is the one
door — member loops, routing, synthesis, everything):

1. **Normalize** — trailing spaces and 3+ newline runs collapse.
   Meaning-preserving, byte-deterministic.
2. **Dedup** — an exact line repeated beyond tolerance collapses to the
   first two occurrences plus an in-place marker naming the elided count.
   Structural lines (headers, lists, fences) never collapse.
3. **Cache-align (measured, never gamed)** — the system text is the prompt
   prefix; identical bytes on the same model across calls is what provider
   prompt caches reward (up to ~90% on reads at the major providers). The
   pipeline measures prefix stability and reports it; it NEVER edits the
   system text to farm hits — an unstable prefix is a correctness choice.
4. **Budget guard** — the old `fitToBudget` remains as the emergency net
   for egregious overshoot (24k-token wire budget), head+tail preserved,
   the cut marked in the text.

**The report is the feature**: each call lands in an event ring; the
console snapshots before a run and aggregates after (`optimDelta`), then
renders `⚡ est −N tok (P%)` on the reply with the full breakdown in the
tooltip — estimates labelled as estimates everywhere, exactly as the
19.2.0 honesty rename demands. The per-call usage ledger
(`vh19.tokens.v1`) still records everything.

## 4. The fleet, grown

### The MCP market (add ANY server)

`src/vh19/mcpMarket.ts` · `probe/mcpMarket` 21 checks.

A curated catalog of 12 reference servers (Filesystem, Git, GitHub,
Postgres, SQLite, Brave Search, Web Fetch, Memory, Sequential Thinking,
Time, Slack, Puppeteer) with declared transports and launch shapes, plus a
user registry: add ANY stdio command or HTTP URL. HTTP URLs pass the same
SSRF egress guard every provider call passes; `sudo`/`rm -rf` command
shapes are refused at the market; env keys are recorded BY NAME, never by
value; everything zod-validated. The export button emits the standard
`mcpServers` JSON the MCP host (`tools/mcp.mjs`), the desktop shell and
any MCP client consume. The honest edge is stated on the panel itself:
the browser registry validates and exports — stdio servers execute under
the host, never secretly from the page.

### The A2A replay guard

`src/vh19/federation/live.ts` (+ `bridge.ts` gains the `"replay"`
refusal class) · `probe/autoRepairReplay`.

A crossing is a state-changing, signed action. A duplicate submission —
a double click or a hostile retry — inside a 60-second window is now
refused in words BEFORE anything is signed or opened, with the refusal
carrying the full CrossingOutcome honesty contract (`attests` /
`notAttested`: it attests the guard refused a duplicate; it does not
attest any crossing outcome, because none ran). Same task after the
window passes: an owner may rerun. Whitespace-cosplay of the same task
is still caught (the signature canonicalizes whitespace).

### Autonomous error handling (the auto-repair rung)

`src/vh19/agentLoop.ts` · `probe/autoRepairReplay`.

The user-facing change: **transient failures stop becoming your problem.**
When a member's provider call dies with a transient kind (timeout,
network reset, unusable response body), the loop retries ONCE
automatically — and it repairs by CHANGING THE SITUATION, per the
failure ladder's own floor: the member is told its prior attempt died
and must answer the original task standalone. No human pause is made or
needed (safe-tier work never gated anyway), and the run is labelled:
`repaired: true` with the reason in words. Non-transient failures (no
key, egress block, HTTP errors) are NOT blind-retried — that is the
exact anti-pattern the ladder forbids. Pinned: exactly two calls on the
repaired path, one on the honest failure.
