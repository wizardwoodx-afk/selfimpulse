# VH 16.9.7 — the production-seam patch (async, host-aware real-model invocation)

*Vouch Harbor 16.9.7 — the accountable agent OS (govern · execute · verify · learn).*

The 16.9.6 external review (9.5/10) found the release's one real production
issue: the real-model planning seam could not actually run in any shipped
bundle. This release fixes the boundary — and proves it end to end.

## The finding, honored

`vite.config.ts` aliases `node:child_process` to the honest web stub (a
WebView cannot spawn processes, and the stub throws rather than fabricate a
success). The 16.9.5/16.9.6 seam imported `execFileSync` directly — so in a
shipped bundle the stub threw, the seam's catch reported "Claude exited 1",
and a CLI that NEVER RAN was indistinguishable from one that failed. A
fabricated exit code is exactly what this product's rules exist to prevent.
The review also flagged the sync spawn (a blocked chat event loop) and the
stale source narrative in vouch.ts. All confirmed, all fixed.

## The fixes

- **HOST-AWARE INVOKE** — the production boundary is now the one that already
  existed: **Tauri → `ipc.cliInvoke` → the Rust bin allowlist → a real
  process** (the same governed route the mission loop's hostDeps uses, argv
  passed explicitly). The **web edition refuses in words** via a typed
  `BrainHostError` BEFORE any spawn is attempted — the module no longer
  imports `node:child_process` at all, so the stub is structurally
  untouchable and no fabricated exit code can exist. Probes and tests inject
  their own invoke (the house dependency-injection pattern).
- **ASYNC BRAIN** — `VouchBrain.decide` admits `VouchPlan | Promise<VouchPlan>`;
  the governed pipeline awaits it. A real model can take a minute; the chat's
  event loop never blocks. Everything downstream is unchanged: same
  simulation, same human gate, same receipts, same learning.
- **STALE NARRATIVE GONE** — the vouch.ts header no longer says "no host app
  and no mission engine yet" or "honestly refused until the merge" (the VH
  engine merged at 16.0); the absence of those phrases is probe-pinned.
- **THE TRUE END-TO-END (scope: the injected probe harness)** —
  `probe/brainSeam` now drives a REAL process: node itself as the harmless
  deterministic harness (prompt passed as data, the same shape a real harness
  adapter uses) — resolved, invoked as a real child process, its output
  parsed into the PLAN, labeled `REAL model — Node runtime · still gated`,
  under the hybrid `simulated+real-plan` identity. The refusal taxonomy pins
  that a host-cannot-spawn refusal is NEVER reported as an exit code.
  STATED PRECISELY: this proves the seam calls an invoke abstraction with a
  real process behind it — it does NOT exercise the Tauri IPC → Rust
  allowlist boundary itself; that boundary was contract-pinned in source
  only (fixed and process-proven in the next release, see below).

## Post-release correction (found by independent review, fixed in 16.10.0)

The review that validated this release also found a **material production
wiring bug** the probe above cannot see: `realBrainInvoke` sent the
TS-resolved ABSOLUTE path (`/usr/local/bin/claude`) as the IPC provider id,
but the Rust gate matches `ALLOWED_CLI_BINS` against BARE names (`claude`) —
so the native desktop path could reach the gate and be refused as
unrecognized. The dependency-injected test never crosses the real IPC, which
is exactly why 41/41 still passed while the production path was broken.

**The 16.10.0 fix** (the reviewer's preferred design — the allowlist stays
the single authority): the seam sends `bareProviderId(bin)` across IPC and
Rust resolves the binary itself (`which_bin`: fast paths + login-shell
paths) behind the unchanged gate. The boundary is now process-proven, not
just contract-pinned: `probe/brainSeam` gained a native-boundary subtest
that pins the wire contract in the Rust source, proves every prefOrder-walk
bin is gate-safe, and mirrors the resolution semantics with a REAL
executable found by bare name through PATH (an absolute-path decoy copy
stays untouched) — through resolve → invoke → parse → REAL label.
