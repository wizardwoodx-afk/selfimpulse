# Vouch Harbor 18.9.0 "Aurora" — upgrade notes

Base: 18.8.0 "Atlas". 18.9.0 is the commercialization-hygiene + capability
release the 18.8.0 review demanded: the product identity is now purely Vouch
Harbor, the licensing no longer contradicts the commercial goal, the bench
grows 252 → 300, and every specialist now runs with a bound **skill
playbook** — the open Agent Skills pattern, rebuilt inside VH's contract.
Protocol unchanged at v0.10.7.

## 1 · Identity & licensing cleanse (the review's blocking finding)

  • **The name is gone.** No personal name appears anywhere in the shipped
    tree — source, docs, manifests, probes, build output. `Cargo.toml`
    authors, README credits, demo scripts, deck outline and test fixtures
    all speak as "the Vouch Harbor team" or generic members.
  • **The predecessor product's identity is gone.** Every "MJ" self-reference
    in active source — mission-layer strings ("MJ has no git runner…"),
    comments, the build define (`MJ_ROOT` → `VH_ROOT`), Settings' copyright
    line — is now VH. 344 files cleaned; the sweep is token-bounded, and the
    gates below prove nothing functional moved with it.
  • **LICENSE replaced.** PolyForm Noncommercial (which forbade the very
    commercial use this product exists for) is retired. The license is now a
    plain proprietary notice: "Copyright (c) 2026 The Vouch Harbor Project.
    All rights reserved." — no personal name, no self-contradiction.
  • **`web-build/` regenerated** from the cleansed tree, so the shipped
    JavaScript no longer contains old identity strings.
  • **Doc drift fixed:** the RELEASE-VERIFICATION opener no longer says
    "111-suite"; the offline count is now self-reported by the runner.

## 2 · Skills — the Agent Skills pattern, VH-native (`src/vh19/skills.ts`)

Research into the open Agent Skills standard (SKILL.md: discovery
description + playbook body, progressive disclosure) is absorbed the VH way
— as a compiled library, not a filesystem convention:

  • **16 playbooks**, each a numbered procedure ending in a quality
    checklist: Premium Interface Craft (the design brief: refuse the
    generic-AI look, hierarchy in greyscale first, design every state),
    Typographic Hierarchy, Colour & Contrast Systems, Spatial Rhythm,
    Evidence-First Security Audit, Assume-Breach Design Review,
    Reproduction-First Engineering, Reversible Change Discipline, Test
    Pyramid Balance, Adversarial Test Data, Source Triangulation,
    Pyramid-First Writing, Assumptions-Visible Analysis, Blast-Radius
    Engineering, Lineage-First Data Trust, Risk-Weighted Review.
  • **Every one of the 300 specialists binds skills** — category defaults
    plus per-specialist extras (design gets the full four-piece premium
    set; security reviews get evidence-first auditing; the database
    engineer gets lineage-trust).
  • **The binding is live instruction, not documentation:**
    `buildSpecialistPrompt()` composes prompt + bound playbooks at run
    time, and that composed prompt is what reaches the provider.
    Progressive disclosure holds: only the routed specialist's skills enter
    context. `probe/skills` pins all of it (16 checks).
