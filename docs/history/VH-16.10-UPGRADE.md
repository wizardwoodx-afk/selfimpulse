# VH 16.10.0 — the production release (six features: a real brain, durable missions, a skill store, the never-give-up loop, always-on triggers, the receipted browser)

*Vouch Harbor 16.10.0 — the accountable agent OS (govern · execute · verify · learn).*

The 16.9.x hardening sequence earned the right to ship the six production
capabilities — each built ON the existing governed machinery (providers on
the llm boundary, durability on the runtime's own persist/restore, skills on
the 16.8 genome, discipline on the arena/verdict engines, triggers on the
governed dispatch, browser on the receipt discipline), each refused-in-words
where its seat is absent, each OFF until a human turns it on.

## The six

1. **UNIVERSAL MODEL PROVIDERS** — the founder's redesign of the brain seam:
   ChatGPT (OpenAI), Claude (Anthropic), Gemini, Groq, OpenRouter, Ollama,
   or any OpenAI-compatible endpoint. BYOK via the local secret store; the
   registry never holds keys. Tier-per-step routing: cheap for routine, big
   for hard. WORK/MANAGE/MONITOR: labeled tiered calls through the governed
   IPC boundary; registry + ping + routes; a usage ledger with ok-rate,
   latency percentiles, per-provider counts and labeled cost estimates.
   Desktop runs every provider through Rust; the web edition runs Ollama
   for real and refuses cloud in words (a browser must not hold cloud keys).
2. **DURABLE MISSIONS** — `MissionRuntime.persist()/restore()` (written in
   12.x, wired by nobody until now) rides a digest-stamped
   `vh-durable-mission/1` envelope: snapshot each step, verify-then-resume,
   refuse tampered snapshots, never repeat finished nodes; the Done ledger
   marks completion only after verified evidence.
3. **THE SKILL STORE** — signed `vh-skill-catalog/1` with real provenance;
   imports verify signature + digest and land UNDER_EVALUATION (shadow,
   trial, auto-rollback): an imported skill re-proves itself on this machine.
4. **THE NEVER-GIVE-UP LOOP** — a standing constraint ledger re-read every
   step; "ask the human" as a real action; proof-before-done: no completion
   claim without verification evidence.
5. **ALWAYS-ON TRIGGERS** — interval/quiet-window triggers dispatch REAL
   governed missions through the SAME human gate; quiet hours, daily caps
   and one-concurrent-run are mechanical; the daemon seat is named, not
   claimed.
6. **THE RECEIPTED BROWSER** — goto/extract for real in any edition
   (accessibility-first fetch mode; native Chromium on desktop); interactive
   actions refuse in words where the seat is absent; every action (executed
   or refused) lands in a hash-chained, exportable action receipt.

7. **THE NATIVE-BOUNDARY FIX** — the 16.9.7 external review's material find,
   fixed per the reviewer's preferred design: the seam sends the BARE
   allowlisted provider id across IPC (`bareProviderId`), the Rust gate stays
   the single authority, `which_bin` resolves the binary server-side, and a
   new `probe/brainSeam` native-boundary subtest process-proves the chain
   (contract pins → gate-safe walk → REAL PATH-resolved executable → REAL
   label). The 16.9.7 release notes were narrowed accordingly: the DI probe
   proved the seam's abstraction, not the IPC boundary — now both are proven.

## 16.10.1 — the integration release (the review's verdict, executed)

The 16.10.0 review scored it honestly: "broader, but less finished — the
implementation has outrun the integration." This patch closes every named
gap; no new features:

- **Provider adapters are real**: groq's true endpoint, `base_url` honored for
  every cloud kind, Anthropic's top-level `system` + required `max_tokens`.
- **Durable missions are the runtime**: the Storage-shape adapter fix, resume
  on `run()`, save after every step, Done-ledger once-guards on verified work.
- **Triggers are always-on for real**: `dispatchMission` dispatch (the governed
  path), a persisted trigger registry, an armed ticker while the window is open.
- **Skill imports mutate the genome**: a persisted `CapabilityGenome` lands
  UNDER_EVALUATION with real provenance; the UI takes the issuer key out-of-band.
- **The receipted browser is bilateral**: desktop click/type/extract ride
  `browser_act`; refusals stay honest wherever a seat is genuinely absent.
- **Web holds no cloud keys**: desktop keychain vs web Ollama-only, in words.
- **Sandbox hardening**: canonicalized containment (symlink-proof) and a
  shell capability boundary (allowlisted CLIs / custom harnesses / in-root
  executables) — not arbitrary programs with a cwd check.

## 16.10.2 — the hygiene patch (the review's final list, deliberately boring)

- **Provider registry default path**: one KV adapter over real Storage /
  injected Map / ephemeral; guarded writes refuse in words. The UI can no
  longer meet an empty provider list that was actually a TypeError.
- **Release hygiene**: the 16.0-era installer filename is gone from all three
  operational docs, and the drift scanner now catches product-named version
  tokens of ANY prefix (VH / VH / Vouch Harbor / `_x64` artifacts).
- **Trigger wording**: "Always-on while Vouch Harbor is open" — the honest
  scope is the title, and the native daemon seat stays named, not claimed.

## What did NOT change

The governed pipeline, the receipt protocol, the human gate, the MCP
surface. Refusals remain in words; nothing fakes; nothing phones home.
