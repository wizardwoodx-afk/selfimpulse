# Vouch Harbor 19.2.0 "Armada" — upgrade notes

Base: 19.1.0 "Shipyard". 19.2.0 is the **make-the-claims-real release**,
answering the two implementation-vs-claim gaps the 19.1.0 review found:
the Captain layer now **actually executes each routed specialist**, and
the live-data GuardRail is now a **runtime control**, not a prompt line.
The token optimizer is renamed to what it honestly is. Protocol
unchanged at v0.10.7.

## 1 · True multi-member execution — the Captain hierarchy now runs

The review was right: 19.1.0 routed N specialists, made **one** provider
call under the first specialist's prompt, then labelled that single run
against all N members. 19.2.0 replaces that in `askVH19`:

```
route (up to 3 specialists)
  ↓
EACH member: own composed prompt → own provider call → own token-ledger
             entry → own result → own member receipt digest
  ↓
Captain report over N real per-member results (each member carries its
own outcome, note and memberDigest)
  ↓
reply = each member's OWN answer, sectioned and attributed — never one
shared answer relabelled N ways
```

Honesty rules, probe-pinned (`probe/captains`, 37 checks): a member whose
own call failed is recorded `error` with the real failure text and the
Captain reads `partial`; when no member executes the run is `error` with
`executed: false` — never a fake synthesis; member receipts are distinct
64-hex digests over each member's own result. One routed specialist keeps
the single-call path. The Shipyard's work orders inherit this
automatically — every order already runs through the same door.

## 2 · The live-data GuardRail, promoted to runtime enforcement

The review was right again: 19.1.0's "GuardRail" was a prompt sentence.
`src/vh19/liveData.ts` is the enforcement, running on **every answered
research/analysis reply** inside `finish()`, whether or not the model
cooperated:

1. **detect_live_data_required** — the ANSWER itself is scanned for
   time-sensitive claims (prices, "latest", CVE ids, `version 3.2`,
   years…). No claims → nothing to enforce (no flag noise).
2. **evidence check** — URLs plus as-of / ISO / month-year dated-claim
   markers in the reply.
3. **verdict** — `verified` (dated live sources present) or a **STALE
   FLAG appended to the reply text itself**, sealed inside the provenance
   digest, stamped in the door (`LIVE-DATA VERIFIED` / `LIVE-DATA
   UNVERIFIED`). A clean stamp over a stale answer is impossible: the
   verdict rides in the canonical.

Honest boundary, stated in the module and the banner: VH ships **no
web-search provider** (no external services by design), so the GuardRail
enforces disclosure — an unverified answer is labelled knowledge-cutoff
data, never dressed as fresh. `probe/liveData`, 17 checks.

## 3 · Honest naming: prompt-budget optimizer

Per the review: ~4 chars/token is an **estimate**, not tokenizer truth.
The module, the door strip and the docs now say **prompt-budget
optimizer · token estimates** everywhere. The budgeting, marked trims
and local usage ledger are unchanged and real.
