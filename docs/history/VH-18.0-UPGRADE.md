## 1 · What ships

### The Generalist front door (`src/vh19/generalist.ts`)
One request in; behind it: GuardRail content scan → the user's learned memory →
the MoE-style router → the human gate for risky work → a REAL provider
execution or an honest non-execution → a provenance-digested response.
The honesty contract is enforced in code, not policy:

- no provider key → `outcome: "planned"`, `executed: false` — a plan in words,
  never a fabricated answer;
- provider failure → `outcome: "error"` with the failure in words;
- risky work with no gate → refused; gate denial → `gated-out`, nothing runs;
- injection at the content gate → refused before routing exists;
- peer delegation without the A2A bridge → refused in words, nothing sent.

### The specialist bench (`src/vh19/registry.ts`)
30 individually specified seed specialists across 10 categories (code,
security, testing, review, data, devops, research, writing, analysis, design),
each with capabilities, routing vocabulary, an honest risk tier from the
product's own vocabulary, a real system prompt and provenance. The catalog
digest is computed (WebCrypto), never hardcoded, and `catalogStats()` reports
the bench's own count — the architecture scales to hundreds of entries; the
shipped count is stated honestly and never padded.

### The MoE-style router (`src/vh19/router.ts`)
The user never picks a specialist. A deterministic keyword/capability scorer
with named reasons is the spine — reproducible, offline, probe-pinned. An
optional LLM re-rank (only when a provider key exists) may REORDER the
deterministic candidates, never invent new ones: ids outside the candidate
set, unparseable JSON or a missing answer all fall back to the deterministic
order with the reason recorded on the decision. `strategy: "none"` is a real
answer — an off-bench request matches nobody and says so.

### The provider seam (`src/vh19/providers.ts`)
OpenAI-compatible, Anthropic and Gemini wire formats behind one `complete()`:
documented base URLs (`api.openai.com/v1`, `api.anthropic.com`,
`generativelanguage.googleapis.com/v1beta`), overridable for
proxies/gateways/local servers; keys from env only, never logged, with a
redaction helper so a key cannot reach a receipt or a report; every base URL
passes the existing SSRF egress guard; timeouts are real; and a missing key is
a typed refusal — the seam never fakes a completion.

### Accept/reject learning (`src/vh19/memory.ts`)
The learning payload is the user's real behavior: accepts, rejects and
corrections, each with a reason, stored local-first per user (capped ledger).
Pattern reports and briefings are computed from real records. Cloud vector
sync is opt-in ONLY and honestly non-operational in 18.0.0: the opt-in is
recorded, `requestCloudSync()` refuses in words, and nothing leaves the device.

### The 90% autonomy exam (`src/vh19/exam.ts`)
How an agent earns gate-free operation on safe-tier work:

1. the exam is generated ONLY from the user's real recorded scenarios — an
   empty history is refused in words, not papered over with invented questions;
2. the agent proposes what it would do AND explains why, per question;
3. the user grades Correct/Wrong; a Wrong becomes a correction record in
   memory (the failure is the learning payload) and the exam is graded
   exactly once;
4. ≥ 90% grants autonomy; < 90% returns to the learning loop. Monitor +
   override is structural — `monitorOverrideAlwaysOn` cannot be stored off,
   and `revokeAutonomy()` is a one-call human act that needs no exam.

### Proof (`probe/vh19.test.ts` — 67 checks)
The whole contract above is pinned: bench integrity, router determinism and
honesty (including the LLM-fallback paths), the three provider wires driven
through a scripted fetch, key redaction in error paths, SSRF refusal, memory
behavior and the truthful cloud-sync state, the exam at the exact 9/10 vs 8/10
boundary, and the Generalist's anti-cheat — no execution claim without
execution, no fabricated answer without a provider, risky work never runs
without a gate.

## 2 · What deliberately does NOT ship in 18.0.0 (and why)

1. **Mastra / AI-SDK source merge** — Mastra core is Apache-2.0 and mergeable;
   the merge is deferred because the release's stated #1 priority is security,
   and a large vendored framework needs its own audit + upgrade pipeline
   before it enters the trust boundary. The provider seam's contract matches
   the AI SDK's shape, so the merge is a drop-in behind the same seam.
2. **300+ specialists** — the registry and router scale to hundreds; the seed
   catalog ships 30 real ones. Padded entries would violate the product's own
   honesty rule.
3. **Cloud vector sync** — opt-in interface only; operational sync is a later
   release with per-user encryption at rest.
4. **MCP surface additions** — the 20-governed-tool count is pinned across the
   probe fleet; expanding it is a deliberate release of its own.
5. **VH-19 UI door** — the engine, probe and honesty contract ship first; the
   chat face wires onto `askVH19` in the next release.
