# Contributing to SelfImpulse

Thanks for considering a contribution. A few rules keep the project honest.

## The standing rule

> Read and understand the implementation before changing it.
> — `docs/IMPLEMENTATION-GAP.md` §5

If a fix touches a gate, a receipt, or a security boundary, understand the
code before you edit it. A patch that silences a probe without understanding
what the probe pins is worse than the bug it hides.

## Three bars every change must clear

1. `npx tsc --noEmit` exits 0.
2. `npm test` (the dev gate) is 171/171. If you add a suite, the count moves
   in `tools/probe-list.mjs` and the offline pack must be rebuilt.
3. `node verify/run.mjs` exits 0. This is the zero-install pack — reviewers
   without node_modules must see the same gate you do.

Run `node tools/rebuild-pack.mjs` when you change anything under `probe/` or
`src/`. It refuses to stamp BUILD-INFO unless all three bars are green, which
is exactly what CI will also refuse.

## Branch hygiene

- Branch off `master`. One logical change per PR.
- Do not hand-edit `verify/BUILD-INFO.txt`, `verify/MANIFEST.json`,
  `verify/suites/*.mjs`, `tools/mcp-engine.mjs`, or
  `tools/vh-host-engine.mjs`. Those are generated by `rebuild-pack.mjs` /
  `mcp:build` / `host:build`.
- Do not bump the engine or product version in a PR; a release is cut from
  a green gate.

## Probes over assertions

If you are fixing a bug, add a probe that fails before your patch and
passes after. The probe is the only reviewer that does not forget.

## Style

- TypeScript strict mode always. No `as any`, no `@ts-ignore`, no
  `@ts-nocheck` (pinned by `probe/codeHygiene.test.ts`).
- Receipts name causes, not just states. "Refused because …" is the form.
- When you refuse, refuse in words. Silent-empty is the failure mode this
  codebase exists to avoid.

## Security

See [`SECURITY.md`](SECURITY.md). Do not open public issues for security
findings.
